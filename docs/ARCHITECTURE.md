# Architecture

## On the TV

```
/media/developer/webosatl/
  bin/            programs (copied from the manager app's payload/ by install.sh / atlmgr)
  runtime.sqfs    ATL runtime image, loop-mounted read-only at runtime/
  runtime.json    sha256 + version of the installed runtime
  home/           HOME of the Android apps (data in home/data/<apk>_, ART cache in home/.cache/art)
  apks/           installed APKs (+ <name>.compat.txt: Android APIs the app uses that ATL lacks)
  logs/           atld.log, apkweb.log, atlmgr.log, init.log
  settings.json   global settings (manager → Settings)
  chromium/       Chromium add-on: browser.sqfs (mounted at chromium/mnt), browserd.sh, profile/, browser.conf
/var/lib/webosbrew/init.d/60-webosatl   boot hook → bin/init.sh start
/media/developer/apps/usr/palm/applications/
  org.webosatl.manager/      manager web app (Homebrew Channel package; payload/ = the TV programs + release.json)
  org.webosatl.app.<slug>/   one native wrapper app per Android app (apk.conf, icon.png, bin/run, bin/xdgshim, run/)
  org.webosatl.chromium/     Chromium wrapper app (Homebrew Channel package; payload/addon.json names the image)
```

### Launching an Android app

1. SAM starts the wrapper's `bin/run` (`tv/run.sh`) inside the app jail.
2. `run.sh` starts `xdgshim -1 /tmp/xdg/wayland-<id>`. That way the window belongs to the launched app's own process
   tree, and LSM only shows windows from there. It then writes `start <socket>` into the FIFO `run/cmd`.
3. `atld` (root, outside the jail) reads the FIFO and runs `runtime/AppRun <apk>` with `WAYLAND_DISPLAY` set to the
   shim socket. `LD_PRELOAD` adds `low4g.so` (ART low-4 GB allocator) and `atlfix.so` (PulseAudio protocol, crash
   backtraces). The environment comes from `apk.conf` `ENV_*` keys and the settings.
4. When the app is closed, `run.sh` gets SIGTERM and writes `stop`. `atld` then ends the app's process session.

Hardware video decoding (`ATL_HWDEC=1`): `run.sh` also starts `atlvdec`, a 32-bit helper. ATL sends compressed
frames to it over a socket (`native/atlvdec/proto.h`). `xdgshim` exports the app window as a webOS video element, so
the hardware video plane shows through it. `ls2-role.sh` gives `atlvdec` the luna-service2 role the media
pipeline needs. The helper has two backends:

- **Starfish** (`sf.c`, LG's `libplayerAPIs`, the buffer-feed pipeline LG's own apps and CSWeb use), for ATL runtimes
  that speak protocol 2. ATL sends every frame as soon as the app queues it, with its pts and the stream's frame
  rate and colour/HDR metadata. The pipeline presents frames by pts at the declared frame rate. When the app
  releases a frame, ATL only sends its due time, and `sf.c` keeps the pipeline's clock on those times. The app's
  clock (its audio) stays the master: Play is timed to the first due time, small offsets are removed by shifting
  the pts of frames not fed yet, the clock is paused when the app stops releasing, and seeks splice the timeline.
- **NDL** (`libNDL_directmedia`, low-delay mode), for runtime 0.1.0 and as the fallback. ATL sends a frame when the
  app releases it, and the helper feeds it at its due time on a smoothed grid.

`ATLVDEC_BACKEND=ndl` (apk.conf `VDEC_ENV`) forces NDL. Audio is unchanged in both: it plays through ATL and
PulseAudio.

### Memory

`atld` follows the foreground app (SAM `getForegroundAppInfo`). By default it allows one Android app at a time,
stops background apps after `idle_stop_min`, closes heavy background apps (browsers, video apps) before a launch,
and sets `oom_score_adj` to 500 for Android apps. See `MEM_DEFAULTS` in `tv/atld.py`.

### Install and updates

- Homebrew Channel installs the manager IPK. On first launch the manager runs `payload/install.sh` as root through
  `luna://org.webosbrew.hbchannel.service/spawn`.
- `atlmgr` checks every minute:
  - payload files that differ from `bin/` are copied over, and the matching services are restarted;
  - if `release.json` names a runtime sha256 that differs from `runtime.json`, it downloads the runtime from GitHub
    Releases (resumable, sha256-checked) and swaps it in when no Android app is running;
  - the Chromium image works the same way, based on its `addon.json`.
- The runtime is not inside the IPK because Homebrew Channel downloads IPKs into RAM.

## Runtime image

Built on an aarch64 host in an Arch Linux container: `runtime/build/build-oracle.sh`. The build pins upstream ATL,
art_standalone, bionic_translation and libopensles-standalone (`runtime/build/versions.env`), applies
`runtime/patches/<component>/*.patch` and packs the result as a sharun AppDir. The TV changes in the patches are
generated by `runtime/tvpatches/*.py` against a git checkout and exported with `git format-patch`. The patches are
the source of truth. `runtime/build/bootimage.sh` then pre-compiles the ART boot image for the TV mount path and
writes the squashfs.
